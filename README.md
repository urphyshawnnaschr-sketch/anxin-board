# 安心看板

**把研发进展讲清楚，让客户看得懂，让项目负责人有据可查。**

安心看板面向承接软件项目的个人、小团队和交付负责人。它结合项目需求与代码变化，通过 AI 辅助整理和人工审阅，把研发工作转成客户能读懂的进度报告，再通过邮件或微信图片交付。

每次汇报，围绕三个客户最关心的问题：**这次做了什么？有什么用？整个项目现在做到哪里？**

## 适合用在什么场景

| 场景 | 常遇到的问题 | 安心看板如何帮助 |
| --- | --- | --- |
| 承接商业项目，向客户汇报进度 | 开发一直在做，客户却只看到零散消息，不清楚项目实际推进了什么 | 把本次工作、用途和项目当前状态放进同一份报告，负责人核对后发给客户 |
| 项目负责人跟进多个功能模块 | 看提交记录只能知道代码变了，难以判断各项需求目前做到哪一步 | 对照确认过的需求与功能范围，整理模块进展、已有依据和仍待核实的事项 |
| 接手已有项目，先摸清现状 | 代码已经不少，但历史完成情况和本轮新增工作混在一起 | 建立项目现状记录，后续汇报分别呈现既有进展与本次改动 |
| 阶段汇报与交付沟通 | 客户不方便打开开发工具，群聊里的口头说明也难以回看 | 输出经人工确认的正式报告，通过邮件附件或微信分页图片查看、留存 |

## 客户收到的报告能看见什么

- **本次工作与价值**：这次具体改了哪里，对使用有什么帮助；负责人可以补充项目背景和实际验证情况。
- **整个项目的进展**：各功能模块当前做到哪一步、已有依据是什么、还有哪些内容待完善或核实。
- **代码变化概况**：新增行数、删除行数和改动文件数，说明本次分析涉及的范围。
- **分析与确认来源**：报告显示实际使用的大模型、已保存的版本记录，以及报告确认信息；需要时可以继续查看 AI 原文与依据。

例如，同样是一次设备状态展示改动，客户更需要知道的是：

> 这次把设备的“在线、离线、状态未知”分开显示，避免无法判断的设备被直接当作离线。报告同时说明这项改动涉及什么，以及真实设备场景中还需要核实什么。

这类说明需要与实际分析结果对应，并由负责人核对，才能进入正式报告。

## 从项目资料到客户收件

**确认需求与代码范围 → AI 整理进展 → 负责人审阅、补充 → 正式确认 → 邮件或微信交付**

1. **准备项目。** 填写项目和 Git 仓库信息，导入需求资料，确认要跟踪的功能模块与分析范围。
2. **整理进展。** 利用已有项目现状和本次代码变化生成分析草稿，保留原始分析与依据。
3. **人工把关。** 负责人核对模块状态，补充客户能理解的说明和实际验证情况，确认报告内容。
4. **交付客户。** 正式确认后，预览报告并核对收件人，再选择邮件发送或微信图片发送。

本次代码变化和整个项目的累计进展分别呈现，已有功能不会被写成本次新增成果。

## 邮件与微信，按客户习惯交付

**邮件**适合正式留档。客户收到邮件正文和可独立打开的 HTML 报告附件。

**微信**适合直接阅读。客户用准备收件的微信扫码绑定后，安心看板可将正式报告转成分页图片；负责人预览、确认后发送，客户在聊天里即可查看，无需另外打开报告网页。

当前版本由安心看板直接管理微信连接，无需单独部署 OpenClaw，也无需先向 ClawBot 发消息。微信账号需具备 ClawBot 使用条件；直接绑定的收件人为完成扫码的账号，当前流程面向单聊。已有 OpenClaw 的用户仍可使用高级接入。

- [微信扫码绑定与收件说明](docs/wechat-qr-setup.md)
- [现有 OpenClaw 高级接入](docs/wechat-openclaw-setup.md)

微信图片复用已确认的报告，不会为发送图片重新调用模型。发送记录保留逐页结果，实际收件以客户手机显示为准。

## 开始使用

安心看板在 **Windows 10/11 本地运行**。使用已交付的 Windows 安装包时，完成安装后通过桌面“安心看板”快捷方式启动，无需自行安装 Python、Node.js 等开发工具。

首次使用准备四项配置：

| 准备项 | 用途与入口 |
| --- | --- |
| 大模型 | 在设置中配置 DeepSeek，完成连接检查并选择可用模型；当前实际接入 DeepSeek |
| 项目代码 | 在项目配置中填写 Git 仓库和研发分支，再确认需求、功能档案与分析起点 |
| 邮箱 | 使用邮件交付时，在项目内进入设置，配置发件服务和本项目收件人 |
| 微信 | 使用微信交付时，在项目的“安心看板”页面点击“绑定微信”，扫码并确认 |

需要从源码运行或制作安装包，请阅读 [开发与部署说明](docs/development.md)。

## 使用前了解这几点

- AI 辅助整理，正式报告由人审阅确认。代码里的实现线索不能替代实际测试或客户验收，代码行数也不是项目完成百分比。
- 产品只读取用户确认的代码范围，不会向被分析的项目仓库自动提交、推送或合并代码。
- 项目记录保存在本机；调用模型时，会按确认范围向模型服务发送分析所需内容。使用者自行配置模型与发件账号，仓库不附带客户数据或可用凭据。
- 当前版本接入 DeepSeek；重新分析、矛盾检测等进阶操作仍受额外准入条件限制，未默认全面开放。具体说明见 [开发与部署说明](docs/development.md)。

本仓库公开提供源码，目前尚未附带开源许可证。
